## 操作流程

1. 保存剪映工程，选择单集草稿及AAF输出目录；首次默认输出D:/Out。
2. 点“检查工程（不导出）”，稍后“刷新任务状态”，再“查看检查报告”。
3. 核对工程名、更新时间、总长、轨道与声道映射，以及素材缺失、已知处理差异、帧率和时间码边界。
4. 点“导出AAF”；导出本身也重新检查，阻止缺失或不支持的基本片段结构。
5. “查看任务结果”定位本次任务；“打开输出目录”访问交付位置。

检查只读草稿，不转换音频或生成AAF。识别缺失素材时汇总多个缺失项，而非静默跳过。已知关键帧、声音效果引用、静音/独奏字段会提示；未识别到不等于所有剪映效果均可还原。帧率仅报告实际可读字段，起始时间码不猜测；当前不写AAF时码轨，前后余量仍为0，立体声仍拆左右单声道。

0.4新增的是目录记忆和预检/报告/状态入口，没有增加分轨、多集、取消任务或后续导入。所有操作从OFX面板触发，没有BAT/CMD或独立导出窗口。

## 原生路径选择

目录选择仅在用户点击按钮时执行，使用Unicode Windows Shell API；取消保持原路径。选择结果通过paramSetValue回写并立即读回核验；宿主拒绝或忽略回写时明确报错，不谎报成功。参数设置为持久化、非动画的路径显示字段；实际工程保存重开仍需在剪映验收。

COM初始化在可用的STA线程使用新目录对话框；已处于其他COM模式时退回兼容目录对话框，不改变宿主线程模式。选取的PIDL使用CoTaskMemFree释放，只有本次成功初始化COM才配对Uninitialize。系统DLL使用系统目录绝对路径加载。

## AAF行为

内嵌48kHz、24位PCM，保留片段裁切、时间线位置和工程尾部静音。固定片段音量和线性淡入淡出烘焙进片段音频。立体声拆成左、右两条AAF单声道轨；更多声道按序号拆轨。重叠片段使用附加轨，保持同时播放位置。全工程从零开始，暂未输出原工程起始时码和视频画面。

缺失素材、同名路径歧义、无法支持的变速/倒放及转换失败会明确报错。没有先输出独立整轨WAV；AAF内嵌媒体所需的片段中间WAV仍存在任务目录里。生成中的AAF带“.未完成”标记，通过结构回读与源草稿一致性检查后才正式命名。

不还原剪映专有音效、关键帧自动化、非线性淡化曲线、轨道静音与独奏。真实加密草稿“22”已通过独立固定读取运行库生成AAF，并验证原稿不变；不保证所有工程或未来版本。目标混音软件真实导入和剪映内按钮完整链路仍待人类实测。
